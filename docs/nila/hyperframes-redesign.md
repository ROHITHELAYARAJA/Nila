# Nila: a softer window into your days

## Shared brief

Rebuild the unified dashboard around the supplied Nila screenshot. Use its navy typography, white canvas, pastel metric cards, glossy weekday orbs, compact chart hierarchy and mint nightly-call banner. Keep the existing Next.js, React, TypeScript, Tailwind, Supabase and Python voice architecture.

The website displays approved telephone answers. It does not ask wellness questions, collect daily manual input, play an agent voice, or create tasks. Each account sees its own data. Missing answers stay unknown. Preview examples remain separate from customer data.

## Page composition

1. Heading and nightly-call banner with an evening-time setting.
2. Mood score ring and aurora orb next to weekday mood cards and mood/stress trends.
3. Water, sleep, energy, stress and explicitly reported goals.
4. Movement, meals, daily reflection and daily win.
5. Voice report and weekly reporting consistency.
6. A gentle footer and an expandable read-only 32-topic collection, keeping the first view compact.

The ring is the mean of reported mood scores multiplied by ten, not a medical assessment. Missing days are gaps, never zero scores. Bars use labeled visual scales rather than invented personal targets. Text remains available for accessibility and essential context.

## Motion contract

- HyperFrames owns decorative orb and moon/cloud artwork. No personal data is baked into video.
- Website components control current water fill, numerical scores and chart points from owner-bound JSON.
- Cards rise gently into view; bars grow from their baseline; selected-day feedback is immediate.
- Pause animations is available in the header. Reduced-motion uses static artwork and removes movement. Offscreen and hidden-page loops pause.
- Mobile has a deliberate two-column metric layout and a scrollable weekday strip. It does not shrink the desktop grid.

## Data journey

Approved voice result → authenticated API saves the call owner's journal in Supabase → private realtime notification → dashboard fetch → current values update the visuals. This redesign preserves that existing connection. New backend wellness fields still require the separate pending migration and Render release.
